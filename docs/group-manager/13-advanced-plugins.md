# ماژول ۱۳ — پلاگین‌های پیشرفتهٔ پیاده‌سازی‌شده (Advanced Plugins)

این سند، پلاگین‌های واقعی‌ای را شرح می‌دهد که به‌صورت کامل (برش عمودی) روی هستهٔ
پلاگین‌محور ساخته شده‌اند و تست می‌شوند — همگی بدون تغییر در هسته و فقط با افزودن
پوشه در `plugins/`.

---

## ۱. پلاگین `moderation` — تنبیه و هشدار پلکانی + دفتر حسابرسی

یک نمونهٔ کامل از «برش عمودی»: فرمان‌ها (لایهٔ نمایش) → تصمیم‌گیری (با قواعد خالص)
→ ثبت در دفتر حسابرسی (زیرساخت). اجرای فیزیکی روی تلگرام (restrict/ban) متعلق به
«آداپتور» است؛ پلاگین تصمیم را می‌گیرد، ثبت می‌کند و پیام نتیجه/علت می‌سازد.

### فرمان‌ها (همگی group-only)
| فرمان | سطح | رفتار |
|---|---|---|
| `ban [دلیل]` | 🔵 ADMIN | بن هدف (ریپلای یا آیدی عددی) |
| `kick [دلیل]` | 🟡 MOD | اخراج |
| `mute` / `unmute` | 🟡 MOD | سکوت/رفع سکوت |
| `tmute <مدت> [دلیل]` | 🟡 MOD | سکوت زمان‌دار (`1h30m`) |
| `unban` | 🔵 ADMIN | رفع بن |
| `warn [دلیل]` | 🟡 MOD | هشدار + اکشن خودکار در آستانه |
| `unwarn` / `warns` | 🟡 MOD / همه | برداشتن هشدار / نمایش |
| `recent` | 🔵 ADMIN | آخرین اکشن‌های دفتر حسابرسی |
| `setstrict <on/off>` | 🔵 ADMIN | حالت «دلیل اجباری» |
| `setwarnlimit <n>` | 🔵 ADMIN | سقف هشدار گروه |

### قواعد ایمنی (در پلاگین، با domain)
1. **مصونیت سلسله‌مراتبی:** مالک ربات هرگز تنبیه نمی‌شود؛ فقط سطح بالاتر می‌تواند پایین‌تر را تنبیه کند (هم‌سطح نه).
2. **دلیل اجباری (strict):** اگر فعال باشد، ban/kick/warn بدون دلیل رد می‌شود.
3. **هشدار پلکانی:** سیاست خالص در `bot/domain/punishment.py`:
   هشدار ۳ → سکوت ۱ ساعت · هشدار ۵ → سکوت ۱ روز · هشدار ۶ → اخراج (پس از اکشن خودکار، هشدارها ریست می‌شوند).
4. **حسابرسی:** هر اکشن (از جمله اکشن خودکار با پیشوند `auto:`) در جدول `actions` ثبت می‌شود و با `/recent` قابل مشاهده است.

> نکتهٔ معماری: «تصمیم‌گیری + ثبت» مستقل از تلگرام است؛ همان‌ها در تست با
> `Dispatcher` اجرا می‌شوند (بدون نیاز به اکانت واقعی).

## ۲. پلاگین `antiflood` — ضد سیل (رویدادمحور)

- به رویداد `message` گوش می‌دهد (اولویت ۲۰۰ = قبل از بقیه) و برای هر `(گروه، کاربر)`
  پنجرهٔ لغزان نگه می‌دارد.
- معافیت‌ها: ادمین‌ها و بالاتر؛ کاربران `mod` و بالاتر هرگز شمارش نمی‌شوند.
- آستانه از تنظیمات گروه: `flood_count` (پیش‌فرض ۵) و `flood_window` (پیش‌فرض ۳ ثانیه).
- هنگام عبور از آستانه فقط **هر ۱۰ ثانیه یک بار** هشدار می‌فرستد (ضد اسپمِ خود ربات).
- اگر پلاگین در گروه خاموش باشد (api.is_enabled) کاری نمی‌کند.

| فرمان | سطح | رفتار |
|---|---|---|
| `antiflood [on/off]` | 🔵 | وضعیت/روشن/خاموش |
| `setflood <count> <seconds>` | 🔵 | تنظیم آستانه (۱–۳۰ پیام / ۱–۶۰ ثانیه) |

## ۳. پلاگین `greeter` نسخهٔ ۲ — خوش‌آمد/خداحافظی پیکربندی‌پذیر

- گوش به رویدادهای `member_joined` و `member_left`.
- متن‌ها با متغیرها: `{name} {username} @{username} {chat} {id} {count}`.
- همهٔ تنظیمات در تنظیماتِ گروه ذخیره می‌شود (نه در کد).

| فرمان | سطح | رفتار |
|---|---|---|
| `greet [on/off]` | 🔵 | وضعیت + پیش‌نمایش / روشن / خاموش |
| `setgreet <متن>` | 🔵 | ذخیرهٔ متن خوش‌آمد |
| `goodbye [on/off]` | 🔵 | خداحافظی روشن/خاموش (پیش‌فرض خاموش) |
| `setgoodbye <متن>` | 🔵 | ذخیرهٔ متن خداحافظی |

## ۴. سوئیچ «پلاگین در هر گروه» (Plugin Toggle)

**قابلیت جدید هسته:** هر پلاگین را می‌توان **در یک گروه خاص** خاموش/روشن کرد
(ذخیره در `settings.plugins` گروه). رفتارها:
- فرمان‌های پلاگینِ خاموش‌شده در آن گروه **بی‌صدا** نادیده گرفته می‌شوند (در پیوی همیشه فعال).
- رویدادهای پلاگینِ خاموش‌شده نیز اجرا نمی‌شوند (پلاگین با `api.is_enabled(chat_id)` چک می‌کند).

| فرمان | سطح | رفتار |
|---|---|---|
| `/plugins` (در گروه) | همه | نمایش وضعیت هر پلاگین: 🟢 فعال / 🔴 خاموش |
| `/pluginenable <name> <on|off>` | 🔵 ADMIN (گروهی) | تغییر وضعیت پلاگین در همین گروه |

**تست‌های سرتاسری اثبات می‌کنند:** خاموش‌کردن `ping` در گروه، `/ping` را بی‌پاسخ می‌کند
ولی در پیوی کار می‌کند؛ خاموش‌کردن `greeter` رویداد خوش‌آمد را متوقف می‌کند.

## ۵. زیرساخت‌های افزوده‌شده به هسته

| مورد | توضیح |
|---|---|
| رویدادهای جدید | `EVENT_MESSAGE`، `EVENT_MEMBER_LEFT` (و `EVENT_CALLBACK` برای فاز دکمه‌ها) |
| جدول `warns` | هر ردیف یک هشدار؛ شمارش/حذف/ریست با `WarnRepo` |
| جدول `actions` | دفتر حسابرسی (audit ledger) با `ActionRepo` و متد `recent/count_today` |
| `domain/punishment.py` | سیاست هشدار پلکانی خالص (`PunishmentPolicy`) |
| `Dispatcher.plugin_enabled` | وابستگی تزریقی برای خاموش‌کردن پلاگین در گروه |
| `PluginAPI` | دسترسی پلاگین‌ها به `api.warns`، `api.actions`، `api.is_enabled/set_enabled` |

## ۶. اجرا و تست

```bash
python3 -m pytest                      # ۱۳۱ تست (شامل تست‌های پیشرفته)
python3 -m bot.main --check            # بارگذاری خودکار همهٔ پلاگین‌ها
```

تست‌ها: `tests/test_advanced_plugins.py` — سناریوهای واقعی بدون تلگرام:
بن/اخراج/سکوت زمان‌دار، مصونیت سطوح، دلیل اجباری، هشدار و اکشن خودکار + ریست،
ضد سیل (هشدار در موج پیام، معافیت ادمین)، خوش‌آمد/خداحافظی سفارشی، و سوئیچ گروهی پلاگین‌ها.

## ۷. نقشهٔ توسعهٔ بعدی (پلاگین‌های باقی‌مانده از سند)

1. **قفل محتوا (`locks`)** — رویداد `message` با بررسی نوع محتوا (لینک/فوروارد/رسانه…).
2. **فیلتر کلمات (`filters`)** — با `domain/text_normalize` و بلک‌لیست گروهی.
3. **CAPTCHA/گیت ورود** — نیازمند «اکشن فیزیکی» آداپتور (restrict عضو) + جدول وضعیت.
4. **کانال لاگ** — ارسال رخدادهای `actions` به کانال لاگ گروه.
5. **آمار** — شمارندهٔ پیام‌ها روی `EVENT_MESSAGE`.
