# ماژول ۵ — قفلهای محتوا (Locks)

هدف: کنترل **نوع محتوایی** که در گروه قابل ارسال است — از «فقط لینک ممنوع» تا «حالت فقط-متنیِ کامل».

---

## ۵.۱. فهرست کامل قفلها (Lockable Items)

### دستهٔ پیام و رسانه
| قفل | چه چیزی را میگیرد | معادل فارسی |
|---|---|---|
| `lock photos` | عکس (غیراز آلبوم با مجوز) | قفل عکس |
| `lock videos` | ویدیو | قفل ویدیو |
| `lock gifs` | انیمیشن/GIF | قفل گیف |
| `lock stickers` | استیکر | قفل استیکر |
| `lock voice` | ویس | قفل ویس |
| `lock video_note` | ویدیوپیام (پینگپنگی) | قفل ویدیو پیام |
| `lock music` | فایل صوتی | قفل آهنگ |
| `lock documents` | فایل | قفل فایل |
| `lock albums` | آلبوم (گالری) | قفل آلبوم |
| `lock animations` | (در برخی کلاینتها) | — |

### دستهٔ متنی و رفتاری
| قفل | چه چیزی را میگیرد | معادل فارسی |
|---|---|---|
| `lock url` | هر لینک (جز لیست سفید) | قفل لینک |
| `lock forward` | پیامهای فورواردی | قفل فوروارد |
| `lock inline` | استفاده از رباتهای اینلاین | قفل اینلاین |
| `lock games` | بازیهای HTML5 | قفل بازی |
| `lock contact` | اشتراک مخاطب | قفل مخاطب |
| `lock location` | موقعیت | قفل موقعیت |
| `lock spoiler` | متن اسپویلر | قفل اسپویلر |
| `lock commands` | دستورهای ربات (برای غیرادمین) | قفل دستور |
| `lock emoji` | ایموجیهای زیاد (آستانهٔ جدا) | قفل ایموجی |
| `lock mentions` | منشن انبوه | قفل منشن |
| `lock caps` | متن تمامحروفبزرگ | قفل حروف بزرگ |
| `lock rtl` | متن راستبهچپِ آینهای (تقلب) | — |

### دستهٔ ساختاری (نیازمند مجوز ادمین تلگرام ربات)
| قفل | اثر | معادل فارسی |
|---|---|---|
| `lock join` | بستن ورود اعضای جدید (لینک دعوت غیرفعال) | قفل ورود |
| `lock bots` | جلوگیری از افزودن ربات | قفل ربات |
| `lock pin` | جلوگیری از سنجاق توسط غیرادمین | قفل سنجاق |
| `lock invite` | جلوگیری از ساخت لینک دعوت توسط غیرادمین | قفل دعوت |
| `lock info` | جلوگیری از تغییر نام/عکس/توضیح گروه | قفل اطلاعات |
| `lock poll` | جلوگیری از نظرسنجی توسط غیرادمین | قفل نظرسنجی |
| `lock service` | خاموشکردن کامل پیامهای سرویس | — |

## ۵.۲. حالتهای رفتار هر قفل (Action Modes)

| حالت | نام | رفتار |
|---|---|---|
| 1 | `silent` (حذف بیصدا) | پیام حذف؛ هیچ اعلانی (پیشفرض برای رسانهها) |
| 2 | `warn` (حذف + هشدار) | حذف + پیام کوتاه «❌ در این گروه {نوع} ممنوع است» برای فرستنده |
| 3 | `notify` (فقط اعلان) | حذف نمیشود؛ فقط یادآوری (برای گروههای آزاد) |

- `setlockmode <mode>` — حالت پیشفرض همهٔ قفلها؛ `lock photos warn` — حالت تکی.

---

## ۵.۳. دستورهای عمومی قفل

| دستور | سطح | رفتار |
|---|---|---|
| `lock <item>` | 🔵 | فعالکردن قفل |
| «قفل لینک» | 🔵 | معادل فارسی |
| `unlock <item>` | 🔵 | آزادکردن |
| `lock all` | 🔴 | فعالکردن **همهٔ** قفلها (حالت فقط-متنی) |
| `lock all except <items>` | 🔴 | همه جز موارد استثنا |
| `unlock all` | 🔴 | آزادکردن همه |
| `locks` | 🟢 | فهرست وضعیت همهٔ قفلها: `🔒 url ✅ ...` |
| `setlockmode all <mode>` | 🔵 | حالت همه |
| `lock <item> <duration>` | 🔵 | قفل زماندار: `lock forward 2h` (خودکار آزاد میشود) |
| `lock <item> <time-range>` | 🔵 | قفل ساعتی: `lock url 23:00-08:00` (شبانه) |

### قفل زماندار/ساعتی — رفتار
- پس از پایان، پیام خودکار: «🔓 قفل فوروارد آزاد شد (مدت ۲ ساعته تمام شد).» در لاگ هم ثبت میشود.
- قفل ساعتی بر اساس **منطقهٔ زمانی گروه** (`settz`) محاسبه میشود؛ اگر زمان شروع = پایان، ۲۴ ساعته تفسیر شود.
- در زمانبندی قفلها از `asyncio.create_task` با کلید `(chat_id, item)` استفاده شود تا دوبار اجرا نشود؛ با ریاستارت ربات، جدول `lock_timers` دوباره بارگذاری شود.

## ۵.۴. استثناها و معافیتها

| مورد | رفتار پیشفرض |
|---|---|
| ادمینها/Mod | همیشه معاف از همهٔ قفلها |
| اعضای معتمد (`settrust`) | معاف از قفلهای رسانهای (نه url) |
| دامنههای سفید | معاف از `lock url` |
| کانالِ لینکشده | معاف از sender-chat |
| عکس پروفایل تغییر | توسط `lock info` گرفته میشود ولی ادمین خود گروه مجاز است (چک سطح قبل از اکشن) |

## ۵.۵. جدول اولویت میان قفلها و ضداسپم (Conflict Resolution)

اگر پیامی همزمان چند قفل را بشکند، فقط **یک** اکشن اجرا شود:
```
1) اسپویلر/متنی (بالاترین اولویت نمایشی) → lock spoiler
2) فوروارد (زیرا حملکنندهٔ محتوای دیگر است) → lock forward
3) لینک در متن → lock url
4) نوع رسانه → lock photos/videos/...
5) منشن/CAPS/ایموجی → (ضداسپم ۲.۷)
6) شمارهگذاری «دلیل حذف» در لاگ: «حذف شد: فوروارد دارای لینک (قفل: forward + url)»
```
پیامِ «حذف شد» باید برای فرستنده دلیلِ **همهٔ** قفلهای شکسته را فهرست کند تا رفتارش اصلاح شود، ولی فقط یک پیام حذف/یک لاگ ثبت شود.

---

## ۵.۶. مثالهای سناریوی واقعی

| سناریو | مجموعهدستور |
|---|---|
| گروه «فقط اعلامیه» | `lock all` سپس `unlock admins`؟ خیر — همه غیر از ادمینها فقط متن ساده: `lock all` + `unlock url`? (مدیر تصمیم میگیرد) |
| گروه فروش (لینک کانال خودشان مجاز) | `lock url` + `whitelist t.me/my_channel` |
| تبلیغات شبانه | `lock url 23:00-07:00` |
| موج فوروارد در جشنواره | `lock forward 6h` |
| گروه چت صوتی آزاد | `lock documents` + `lock contact` + `lock url warn` |

## ۵.۷. داده (Schema)
```jsonc
locks: { chat_id, item, action: 1|2|3, until: null|unix, hours: null|"23:00-08:00", by }
```
هر تغییر قفل → لاگ: «🔒 قفل عکس فعال شد (حالت: حذف+هشدار) توسط @admin».
