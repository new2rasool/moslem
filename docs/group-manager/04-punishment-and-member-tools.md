# ماژول ۴ — تنبیهها و ابزار مدیریت اعضا و پیام (Member & Message Tools)

هدف: ابزارهای روزمرهٔ مدیر — تنبیه منصفانه، پاکسازی، سنجاق، عنوان و مدیریت تیم مدیریت.

---

## ۴.۱. دستورهای تنبیهی (Punishments)

| دستور | سطح | پارامترها و نمونه |
|---|---|---|
| `ban` / «بن» | 🔵 | ریپلای یا ذکر: `ban @user`, `ban 123456`, `ban <دلیل>` |
| `tban <مدت>` / «بن ۲ ساعت» | 🔵 | `tban 2d @user spam` — بن موقت با دلیل |
| `unban` / «آنبن» | 🔵 | ریپلای/ذکر — برداشتن بن |
| `kick` / «اخراج» | 🟡 | اخراج بدون بن (عضو میتواند با لینک برگردد) |
| `kickme` / «اخراج من» | 🟢 | خروج داوطلبانه (در گروههای عمومی) |
| `mute` / «سکوت» | 🟡 | `mute @user <دلیل>` — سکوت نامحدود |
| `tmute <مدت>` / «سکوت ۱۰ دقیقه» | 🟡 | `tmute 10m` — سکوت زماندار |
| `unmute` / «رفع سکوت» | 🟡 | برداشتن سکوت |
| `dmute` / `dkick` / `dban` | 🔵/🟡 | «حذف پیام + اکشن» در یک گام |

### مشخصات مدتزمان (پارسر واحد)
- واحدها: `s` ثانیه، `m` دقیقه، `h` ساعت، `d` روز، `w` هفته.
- ترکیب: `1d6h30m` معتبر است؛ بدون واحد = دقیقه (`tban 90` = ۹۰ دقیقه).
- سقف: tban ≤ 366 روز (محدودیت تلگرام)؛ tban از ۲ دقیقه کمتر نباشد (خطای API).

### دلیل اجباری (Strict Mode)
- `setstrict on` (🔵): بن/اخراج/سکوتِ بدون دلیل رد میشود: «⚠️ در حالت سخت، دلیل لازم است: `ban @user <reason>`».
- دلیل در اعلان کاربر، لاگ و (در صورت GBan) پیام گروههای دیگر درج میشود.

### اعلان به کاربر (پیوی — اگر ربات را استارت کرده باشد؛ وگرنه همانجا در گروه)
```
🔨 شما از گروه «انجمن برنامهنویسی» بن شدید.
📝 دلیل: تبلیغ اسپم
🕐 توسط: @admin — تا: 2026-09-06 21:04 (برای tban)
[📩 درخواست تجدیدنظر]  ← دکمه ارسال به ادمینها (فقط اگر مدیر فعال کرده باشد)
```

### قواعد ایمنی (Safety Rules)
1. **مصونیت سلسلهمراتبی:** سطح پایینتر نمیتواند سطح بالاتر را تنبیه کند (Mod نمیتواند Admin را mute کند).
2. ⚫/🔴 مصون از همه.
3. **سقف روزانه:** هر ادمین پیشفرض حداکثر ۵۰ اکشن در روز (`setdailylimit <n>`) — ضد خطای انسانی و ادمین دیوانه.
4. **بازگشتپذیری:** همهٔ اکشنها در لاگ با «دکمهٔ خنثیسازی» (برای ۱۰ دقیقهٔ اول) ثبت میشوند: `↩️ undo` — ادمین بالاتر میتواند اکشن همکارش را برگرداند.
5. اگر هدف خودِ ربات باشد → نادیده + لاگ «تلاش به تنبیه ربات».

## ۴.۲. پاکسازی پیامها (Purge & Delete)

| دستور | سطح | رفتار |
|---|---|---|
| `del` (ریپلای) / «حذف» | 🟡 | حذف همان پیام (با `delete_messages`، حتی اگر فرستندهاش غیرادمین باشد) |
| `purge` (ریپلای) / «پاکسازی» | 🟡 | حذف همهٔ پیامهای بین پیامِ ریپلای و دستور |
| `purge <n>` | 🔵 | حذف n پیام آخر (۱–۱۰۰۰) |
| `purge <reply> <n>` | 🔵 | n پیام بعد از پیامِ ریپلای |
| `spurge` | 🔵 | پاکسازی بیصدا (بدون پیام «انجام شد») |
| `delall <id|@user>` | 🔵 | حذف آخرین ۱۰۰ پیام یک کاربر (با جستجوی message history؛ محدود به آنچه تلگرام میدهد) |
| `setcleanup on/off` | 🔵 | حذف خودکار «دستور مدیر» و پاسخ ربات پس از ۲۰ ثانیه در گروههای شلوغ |

**محدودیتها و نکتهها:**
- پاکسازی بیش از ۵۰ پیام، با `delete_messages` در دستههای ۱۰۰تایی و با خواب ۰.۵ ثانیهای انجام شود (ضد 429).
- اگر بین پیامِ ریپلای و دستور، پیامِ سرویس یا «ورود عضو» بود، حذف آن نیاز به مجوز `can_delete_messages` دارد و انجام میشود.
- حداکثر `purge` = ۱۰۰۰ پیام؛ بیش از آن خطای «برای پاکسازی گسترده با مدیریت تماس بگیرید».
- **پیامهای یک ادمین دیگر** قابل حذف با purge نیست (مگر 🔴) — قانون ضد سوءاستفاده.

## ۴.۳. سنجاق (Pins)

| دستور | سطح | رفتار |
|---|---|---|
| `pin` (ریپلای) | 🔵 | سنجاق + اعلان |
| `pin silent` | 🔵 | سنجاق بیصدا (`disable_notification=true`) |
| «سنجاق» | 🔵 | معادل فارسی |
| `unpin` (ریپلای/خالی) | 🔵 | برداشتن سنجاق (خالی = آخرین سنجاق) |
| `unpinall` | 🔴 | پاککردن همهٔ سنجاقها (سقف تلگرام: نمایش فقط ۵ تای اخیر) |
| `pinned` | 🟢 | نمایش آخرین پیام سنجاقشده |

- سنجاق خودکار قوانین هنگام فعالشدن گیت: `autopinrules on/off`.

## ۴.۴. عنوان و برچسب (Titles)

| دستور | سطح | رفتار |
|---|---|---|
| `settitle <text>` (ریپلای) | 🔵 | عنوان اختصاصی بالای نام کاربر (نمونه: «⭐ ناظر») |
| `settitle` بدون متن | 🔵 | برداشتن عنوان |
| `chatitle <text>` | 🔵 | تغییر نام گروه (در صورت مجوز) |
| `titlelist` | 🔵 | فهرست اعضای دارای عنوان |

- عنوان در `getChatMember` کاربر (فیلد `custom_title`) ذخیره میشود — فقط برای اعضای دارای رتبهٔ ادمین/مالک تلگرام ممکن است؛ برای کاربر عادی باید ابتدا با مجوز حداقلی `can_change_info` ارتقا یابد یا از «نام نمایشی در لیست مدیرانِ ربات» استفاده شود (روش جایگزین: تگ کنار اسم در لیست `adminlist`).

## ۴.۵. ارتقا و ساختار تیم مدیریت (Promote/Demote)

### نقشهای ربات (Robot-Roles — بدون تغییر نقش تلگرام)
| نقش | دسترسی (نمونهٔ کامل در جدول بعدی) |
|---|---|
| 🟡 Mod (مدیر میانی) | warn/dwarn/mute/tmute/kick/del/purge ≤50/report رسیدگی/… |
| 🔵 Admin (ادمین ربات) | همهٔ Mod + ban/tban/pin/setitle/setrules/تنظیمات ضداسپم/فیلترها |
| 🔴 Co-owner (معاون مالک) | همهٔ Admin + ارتقا Mod/Admin + تنظیمات گروه + strict |
| 🔴 مالک گروه | همه + تعیین Co-owner/Admin + تغییر preset + خروج ربات از گروه |

### دستورها
| دستور | سطح | رفتار |
|---|---|---|
| `promote @user <mod/admin/co>` | 🔴 (برای admin: فقط mod) | ارتقا با سطح |
| «ارتقا» | — | معادل فارسی |
| `demote @user` | 🔴 | تنزل یک پله (و اگر 🔵 باشد حذف کامل) |
| `promote @user admin --tg` | 🔴 | ارتقای **همزمان در تلگرام** با انتخاب مجوزها (بدون `--tg` فقط نقش رباتی) |
| `myperms` | هرکس | نمایش دسترسی خودش در این گروه |
| `adminlist` / «مدیران» | 🟢 | فهرست: مالک، Co-ownerها، ادمینها، مادها + عنوان |
| `owner` | 🟢 | نمایش مالک گروه |

### ماتریس کامل دسترسی (مرجع پیادهسازی)
| قابلیت | 🟢 | 🟡 Mod | 🔵 Admin | 🔴 Co/Owner |
|---|---|---|---|---|
| گزارش / قوانین / kickme / id | ✅ | ✅ | ✅ | ✅ |
| warn / unwarn / mute / tmute / kick / del | ❌ | ✅ | ✅ | ✅ |
| purge ≤۵۰ | ❌ | ✅ | ✅ | ✅ |
| ban / tban / unban / purge کامل / pin | ❌ | ❌ | ✅ | ✅ |
| افزودن blacklist / فیلتر / قفل | ❌ | ❌ | ✅ | ✅ |
| setrules / captcha / antiflood / strict | ❌ | ❌ | ✅ | ✅ |
| promote Mod / demote Mod | ❌ | ❌ | ✅ | ✅ |
| promote Admin+ / تنظیمات مالکانه / preset | ❌ | ❌ | ❌ | ✅ |
| خروج ربات / تغییر مالک | ❌ | ❌ | ❌ | ✅ (فقط مالک) |

> `setrole perms` — امکان سفارشیسازی دقیقتر: «Mod بدون حق mute دائم» و… (جدول مجوزهای ریز، ۴۰+ مجوز).

## ۴.۶. بهداشت اعضا (Hygiene)

| دستور | سطح | رفتار |
|---|---|---|
| `zombies` / «پاکسازی» | 🔵 | اسکن `get_chat_members` برای اکانتهای حذفشده (`deleted account`) |
| دکمهٔ `✅ حذف N مورد` | 🔵 | حذف پس از تأیید (هرگز خودکار بدون تأیید) |
| `inactive <days>` | 🔴 | فهرست اعضای N روز غیرفعال (فقط گزارش؛ حذف دستی توسط مدیر) |
| `invitelink` | 🟡 | نمایش لینک دعوت فعلی (نیازمند مجوز invite) |
| `setchatpic` / `setchatdesc` | 🔵 | تنظیم عکس/توضیح گروه (در صورت مجوز) |
| `setjoinfrequency ...` | 🔴 | (اختیاری) محدودکردن سرعت ورود با لینک |

## ۴.۷. اطلاعات کاربر

| دستور | سطح | خروجی |
|---|---|---|
| `id` (ریپلای/ذکر/خالی) | 🟢 | آیدی کاربر/گروه/پیام |
| «آیدی» | 🟢 | معادل فارسی |
| `info` (ریپلای/ذکر) | 🟡 | کارت کامل: نام، یوزرنیم، آیدی، تاریخ عضویت، نقش، هشدارها، وضعیت (محدود؟ بن؟)، لینک پروفایل، آیا ربات را استارت کرده |
| `whois` | 🔵 | `info` + سابقه: چند بار بن/اخراج شده، چند هشدار در ۳۰ روز، در چند گروهِ تحتِ مدیریت مشترک است (برای تشخیص چندکاربره) |
| `dc <id>` | 🔴 | (پیشرفته) تشخیص دیتاسنتر اکانت برای کشف چنداکانته |

**کارت نمونهٔ `info`:**
```
👤 علی رضایی (@alireza)
🆔 123456789 | [پروفایل]
📅 عضویت: ۱۴۰۴/۰۲/۱۱ (۴۹۶ روز)
🎖️ نقش: 🔵 ادمین ربات — عنوان: «⭐ ناظر»
⚠️ هشدار: ۱ از ۳ (انقضا: ۷ روز)
🚫 وضعیت: عادی
```

## ۴.۸. محافظت از مالک گروه در برابر «کودتا»

- اگر 🔵 بخواهد 🔴 را بن/کیک کند → مسدود + هشدار به مالک در پیوی.
- اگر ربات از گروه اخراج شود، در لحظهٔ خروج یک «اسنپشات تنظیمات» به کانال مالک ارسال میشود تا هنگام نصب مجدد، همهچیز برگردد (بازیابی با `import`).
- انتقال مالکیت: `transferowner @user` — فقط مالک کنونی؛ تأیید دومرحلهای (دکمه).
