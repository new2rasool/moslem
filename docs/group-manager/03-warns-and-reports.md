# ماژول ۳ — سیستم هشدار و گزارش (Warnings & Reports)

هدف: مدیریت رفتار بد **با شفافیت و عدالت** — کاربر بداند چرا و چند هشدار دارد؛ مدیر ابزار دقیق و
بدون «بنِ یکبارهٔ خودسرانه» داشته باشد.

---

## ۳.۱. سیستم هشدار چندسطحی

### دستورها
| دستور | سطح | رفتار |
|---|---|---|
| `warn` (ریپلای) | 🟡 | +۱ هشدار با دلیل اختیاری (`warn <reason>`) |
| «هشدار» | 🟡 | معادل فارسی |
| `dwarn` (ریپلای) | 🟡 | حذف پیام + هشدار (با ذکر دلیل در پیام اعلان) |
| `swarn` (ریپلای) | 🔵 | هشدار بیصدا: فقط در کانال لاگ ثبت میشود، کاربر متوجه نمیشود (برای جمعآوری سابقه) |
| `unwarn` (ریپلای) | 🟡 | برداشتن آخرین هشدار |
| `unwarn all` | 🔵 | پاککردن همهٔ هشدارهای کاربر |
| `warns` (ریپلای/ذکر) | 🟡 | نمایش وضعیت: «۲ از ۳ هشدار — هشدار بعدی: سکوت ۱ ساعته» |
| «هشدارها» | 🟡 | معادل فارسی |
| `setwarnlimit <n>` | 🔵 | حداکثر هشدار (پیشفرض ۳؛ بازه ۱–۱۰) |
| `setwarn action <n>` | 🔵 | جدول اکشنهای خودکار |
| `setwarnexpire <days>` | 🔵 | انقضای هشدار (پیشفرض ۷ روز؛ 0 = هرگز) |

### جدول اکشن خودکار (متناظر با تعداد هشدار)
| هشدار | اکشن پیشفرض | قابل تغییر به |
|---|---|---|
| ۱–۲ | فقط اعلان | — |
| ۳ | 🔇 سکوت ۱ ساعت | mute 5m/1h/1d / kick |
| ۵ | 🔇 سکوت ۱ روز | — |
| حداکثر (پیشفرض ۶) | 👢 اخراج | kick/ban/tban |

> با `setwarn action` میتوانید مثلاً «در هشدار ۳ = اخراج» بگذارید و «۶» را غیرفعال کنید.

### اعلان به کاربر (همیشه در پیوی اگر ربات را استارت کرده باشد)
```
⚠️ هشدار ۱/۳ — گروه: انجمن برنامهنویسی
📝 دلیل: توهین به عضو دیگر (توسط @admin)
🕐 امروز 21:04 — این هشدار ۷ روز دیگر پاک میشود.
```

### قواعد منصفانه
- **انقضا:** هشدارها پس از N روز خودکار حذف میشوند (بخشش مرور زمان).
- **مصونیت:** هشدار روی ⚫/🔴/مالک گروه ممکن نیست؛ روی 🔵 فقط توسط 🔴.
- **پاکسازی:** با `ban` دائم، هشدارهای کاربر پاک میشود؛ با `kick` نه.
- **دفاع:** اگر کاربر ۳ بار پشتسرهم توسط یک ادمین خاص هشدار بیپاسخ بگیرد و تیم داوری نداشته باشد → پرچم «⚠️ احتمال سوءاستفاده از هشدار توسط {admin}» برای 🔴 ارسال میشود.
- **خوداظهاری:** `warns` برای کاربر عادی فقط «هشدارهای خودش» را نشان میدهد؛ ادمینها همه را میبینند.

## ۳.۲. گزارش ناشناس (Anonymous Reports)

### دستورها و دکمهها
| مورد | توضیح |
|---|---|
| `report` (ریپلای) | گزارش یک پیام |
| «گزارش» | معادل فارسی |
| دکمهٔ «🚩» روی پیامهای حساس | اگر مدیر «دکمهٔ گزارش» را در قالب پیام فعال کرده باشد |
| `setreport limit <n>` | پیشفرض ۳: آستانهٔ گزارش برای ارسال به ادمینها |
| `setreport to <admins/channel>` | مقصد اعلان: پیوی ادمینها / کانال لاگ |

### جریان دقیق
1. کاربر روی پیامِ متخلف `report` میزند → ربات: «✅ گزارش شما ثبت شد. سپاس از مشارکتتان.»
2. هر گزارش +۱ روی شمارندهٔ همان پیام (با `message_id` کلید میخورد).
3. وقتی به آستانهٔ (پیشفرض ۳) رسید → برای همهٔ 🔵/🟡 ادمینهای آنلاین در پیوی ارسال میشود:
```
🚩 گزارش جدید (گزارش ۳ از ۳)
👤 فرستنده: {name} (id)
📄 متن: «...» (حداکثر ۲۰۰ کاراکتر)
🔗 [مشاهدهٔ پیام]
[✅ سالم بود] [⚠️ هشدار] [🔇 سکوت] [👢 اخراج] [🔨 بن]
```
4. اولین ادمینی که اکشنی انتخاب کند، برنده است؛ بقیه دکمهها غیرفعال میشوند.
5. اگر ۱۵ دقیقه هیچ ادمینی پاسخ نداد → گزارش در کانال لاگ «بدون پاسخ» بایگانی میشود.

### ضد سوءاستفاده از گزارش
- هر کاربر عادی حداکثر **۵ گزارش در ساعت** (پیشفرض؛ `setreport userlimit <n>`).
- گزارشهای «تکراریِ بیدلیل» (مثلاً ۳ گزارش روی پیامهای سالم یک کاربر) → خودِ گزارشگر هشدار میگیرد (`dwarn`).
- گزارشگر هرگز فاش نمیشود؛ حتی برای ادمینها فقط «گزارشگر: کاربر ناشناس» + کد کوتاه مثل `#R4821` برای رهگیری در لاگ.

## ۳.۳. اکشنهای خودکارِ مکمل (Action Triggers)

| Trigger | رفتار پیشفرض |
|---|---|
| ۳ شکست CAPTCHA | اخراج (ماژول ۱) |
| ۵ تخلف ضداسپم در ۱ ساعت | هشدار خودکار |
| ورود از لیست سیاه سراسری | بن خودکار (ماژول ۲) |
| ۱۰ گزارش معتبر روی یک کاربر در ۱ روز | بررسی خودکار توسط 🔴 (پیام ویژه) |

**طراحی داده:**
```jsonc
warns:   { chat_id, user_id, count, list: [{reason, by, at, expires_at}] }
reports: { chat_id, message_id, target_user, count, reporters:[{uid, at}], status:"open|resolved|expired" }
```
ایندکس ترکیبی `(chat_id, user_id)` روی هر دو جدول؛ پاکسازی روزانهٔ هشدارهای منقضی با تسک شبانه.
